For every git push in Trip_Tracker_2026 (and as a general preference across projects), commit messages must be detailed and complete: type prefix, clear title, and dash-bulleted body covering what changed and why (not just a one-liner). Always follow this repo's CLAUDE.md pre-push workflow too: ask bug-fix vs feature before pushing, bump package.json version, restart the dev server, log the change (bugs/bugs.json+BUGS.md or features/features.json+FEATURES.md via scripts/feature.mjs), and document it in decisions.md.
